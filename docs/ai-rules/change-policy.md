# Change Policy

Это защищает от типичной проблемы AI-разработки: модель начинает “улучшать всё сразу”.

- одна задача = один завершённый логический результат
- не менять более одной подсистемы за один шаг без явной причины
- не смешивать рефакторинг и новую функциональность
- сначала прототип/спека, потом код
- сначала минимально рабочая версия, потом улучшения
- перед большим рефакторингом или крупными изменениями сделать backup/commit
