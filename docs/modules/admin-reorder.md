# Перетаскивание товаров, навигации и FAQ в админке

/admin/edit?section=products: список разбит по категориям в порядке лендинга.
За ручку с точками товар перемещается мышью или касанием внутри категории.
Pointer Events, захват после DOM-перемещения, touch-action:none только на ручке;
остальная страница прокручивается обычным способом. У края окна работает автопрокрутка.
После движения на 5 px строка поднимается: визуальная копия следует за указателем
с сохранением точки захвата, а исходная строка обозначает место вставки пунктиром.
Соседи плавно сдвигаются (FLIP, Web Animations API, 240 ms); пороги перестановки
считаются по координатам раскладки, независимо от анимации. При отпускании копия
плавно опускается на новое место, затем сохраняется порядок. При отмене она возвращается
на исходное место. Копия inert/aria-hidden, без ID и JS-хуков; формы не дублируются
для доступности. Геометрия задаётся Web Animations API, без inline-стилей.
При prefers-reduced-motion сдвиг и приземление мгновенные, следование за указателем
сохраняется. Автопрокрутка усиливается по мере приближения к краю окна.
Область статуса резервирует высоту во всех списках: начало перетаскивания не сдвигает
строки относительно курсора.
Клавиатура: Enter/Space — начать, стрелки/Home/End — переместить, Enter/Space — сохранить,
Escape — отменить. Потеря фокуса окна, pointercancel и отпускание вне списка отменяют.
Кнопок «Выше»/«Ниже» нет. Без JS ручки скрыты, чтение и редактирование доступны.

POST /admin/products/reorder: активная сессия, CSRF, категория, полный уникальный
список её ID, версия порядка (SHA-256 массива ID). Несовпадение состава — 422,
устаревшая версия — 409. Все sort_order обновляются одной SQLite-транзакцией,
остальные данные не меняются. Новый товар и перенос в другую категорию — в конец.
Ручное поле порядка у товара заменено перетаскиванием.

Во время сохранения ручки отключены и aria-busy=true. Ошибка возвращает прежний
визуальный порядок и выводится через notify.js. Конфликт требует обновить страницу.
Ручки, подсказка и aria-live доступны скринридеру. JS: admin.js -> admin-reorder.js;
сборка выпускает отдельный admin.js с хешем, на лендинге он не подключается.

Проверки: HTTP (401/403/422/409, атомарность и порядок HTML), Playwright в отдельной
БД: мышь, перезагрузка, клавиатура, Escape, 503 с откатом и эмулированное касание.

## Навигация и вопросы

По поручению пользователя тот же Pointer Events-модуль работает в разделах
navigation и faq: ручки слева, сохранение после отпускания, клавиатура и отмена.
POST /admin/records/reorder принимает section из белого списка navigation/faq,
полный набор ID включая скрытые записи, version и CSRF. Другой раздел запрещён.
Нельзя убрать, добавить или повторить ID. Устаревшая версия получает 409.
saveRecordOrder обновляет только sort_order одной транзакцией; публичные
навигация и FAQ читают тот же порядок. Скрытые записи остаются скрытыми.
Числовое поле порядка в редакторе сохранено как альтернатива без JavaScript.
После перетаскивания FAQ старые номера порядка в строках не показываются.
Шаблоны reorder-help/attributes/handle общие для этих двух списков.
Проверки: tests/integration.py и tests/admin-record-order-browser.cjs
на отдельной QA-базе (мышь, клавиатура, Escape, перезагрузка и 503 с откатом).

Плавность: tests/admin-reorder-motion-browser.cjs проверяет порог начала, сохранение
точки захвата по обеим осям, место вставки без дрожания, приземление, Escape,
единственный запрос после отпускания, reduced motion, ширину 320 px и отмену вне списка.
Все браузерные сценарии и tests/integration.py пройдены на отдельной тестовой базе.
