# Админка: согласованная спецификация

## Решение и границы
PHP-сайт и /admin на одном хостинге; SQLite через PDO, PHP 8.2+, MVC на функциях,
шаблоны .tpl. Один администратор создаётся только CLI. Сохранение сразу публикует
данные. CSS/JS остаются нативными. Заказы, оплата, персональные данные гостей,
метки товаров и универсальный конструктор страниц исключены.

## Данные
- Категории: название, порядок, видимость. Нельзя удалить категорию с товарами.
- Товар: стабильный ID, категория, название, описание, состав, порция, целая цена
  в рублях, фото/alt, порядок, видимость, наличие. Скрытый не выводится; отсутствующий
  виден без добавления. Архивирование — скрытие, удаление отдельно и явно.
- Контакты: название, город, улица, телефон, реальная ссылка карты (не задана по умолчанию).
- График: по дням недели, закрытые дни; исключение на конкретную дату выше обычного
  графика. Время и даты — Asia/Yekaterinburg; ночные интервалы в первой версии не поддержаны.
- Получение: включение самовывоза/доставки, целые рубли тарифа/порога, зона и сроки.
  Нельзя отключить оба способа. Пустая корзина — нулевая доставка; порог включительно.
- Контент: тексты и фотографии существующих блоков, подписи CTA и alt; структура
  секций остаётся заданной шаблоном. Свободные тексты — обычный текст без HTML.
- Навигация: подпись, существующий якорь из белого списка, порядок, видимость.
- FAQ: вопрос, ответ, порядок, видимость. Служебные ответы о графике и доставке
  формируются из настроек; свободные упоминания администратор обновляет вручную.
- Объявления: текст, включение, начало/окончание включительно по локальному времени.
- Отзывы: автор, текст, реальный источник, порядок, видимость. Пустой раздел видим с сообщением «Отзывов пока нет».
  Рейтинг: значение, количество, URL источника; без источника не публикуется.
- SEO: title, description, OG title/description, отдельное описание schema.org,
  превью JPG с alt, просмотр изображения и счётчики символов. JSON-LD создаётся из
  контактов, графика, каталога, видимых FAQ; не редактируется произвольным JSON.

## Единый источник
После миграции SQLite — источник рабочего контента. product.md и landing-content.md
описывают начальные демо-данные и редакционную основу, не переписывают БД при запуске.
Каталог питает карточки и строки корзины. Контакты/график/доставка питают подвал,
первый экран, бегущую строку, служебные FAQ и JSON-LD. SEO с ценой выводит актуальную
минимальную цену отдельно от свободного description. Произвольных подстановок нет.

## Безопасность и хранение
Все изменения POST + CSRF, серверная валидация, экранирование вывода, PDO-параметры.
Сессии HttpOnly/SameSite, Secure по HTTPS, таймаут, обновление ID после входа.
Ограничение попыток по IP с хранением в SQLite; доверять X-Forwarded-For нельзя.
SQLite, логи, копии и сессии в приватном каталоге вне публичного корня на хостинге.
Загрузки только растровые, MIME/размер/пиксели проверяются, имена случайные.
Резервная копия БД и полный ZIP с изображениями; восстановление проверяет формат,
схему и пути, требует явного подтверждения и создаёт предварительную полную копию.

## Приёмка
Редактирование каждого типа отражается на странице, меню читается без JS.
Корзина работает с произвольным количеством товаров и новыми ценами, без отправки.
Особые даты, пустые коллекции, скрытые категории и границы доставки проверены.
Установка не содержит известного пароля; повторная миграция сохраняет правки.
Обновление приложения не заменяет рабочую БД/загрузки. Копия восстанавливается
в изолированном окружении. Проверки и ограничения записываются в ADMIN-PLAN.md.
