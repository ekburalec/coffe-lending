# Перетаскивание товаров в админке

/admin/edit?section=products: список разбит по категориям в порядке лендинга.
За ручку с точками товар перемещается мышью или касанием внутри категории.
Pointer Events, захват после DOM-перемещения, touch-action:none только на ручке;
остальная страница прокручивается обычным способом. У края окна работает автопрокрутка.
Клавиатура: Enter/Space — начать, стрелки/Home/End — переместить, Enter/Space — сохранить,
Escape — отменить. Потеря фокуса окна, pointercancel и отпускание вне списка отменяют.
Кнопок «Выше»/«Ниже» нет. Без JS ручки скрыты, чтение и редактирование доступны.

POST /admin/products/reorder: активная сессия, CSRF, категория, полный уникальный
список её ID, версия порядка (SHA-256 массива ID). Несовпадение состава — 422,
устаревшая версия — 409. Все sort_order обновляются одной SQLite-транзакцией,
остальные данные не меняются. Новый товар и перенос в другую категорию — в конец.
Ручное поле порядка у товара заменено перетаскиванием.

Во время сохранения ручки отключены и aria-busy=true. Ошибка возвращает прежний
визуальный порядок и выводится через notify.js. Конфликт требует обновить страницу.
Ручки, подсказка и aria-live доступны скринридеру. JS: admin.js -> admin-reorder.js;
сборка выпускает отдельный admin.js с хешем, на лендинге он не подключается.

Проверки: HTTP (401/403/422/409, атомарность и порядок HTML), Playwright в отдельной
БД: мышь, перезагрузка, клавиатура, Escape, 503 с откатом и эмулированное касание.
