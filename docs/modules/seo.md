# SEO управляемого лендинга

Редактор /admin/edit?section=seo: title, description, OG title/description и JPG
1200×630. При загрузке JPG/PNG/WebP сервер создаёт JPG нужного размера. Свободные
SEO-тексты не содержат автоматических подстановок; цены выводятся в структурированном
меню и priceRange из текущих товаров. Из начального description удалена фиксированная
цена, чтобы изменения каталога не оставляли старое обещание.
JSON-LD: CafeOrCoffeeShop, адрес, график/особые даты, Menu/MenuSection/MenuItem/Offer,
FAQPage из видимых ответов. Нет выдуманного рейтинга. JSON_HEX_* предотвращают выход
из script при вводе HTML. Вывод атрибутов экранирован. site_url и noindex задаются
в config/deploy.php; без домена разрешён только предварительный режим.

robots.txt, sitemap.xml, llms.txt и llms-full.txt — динамические маршруты, поэтому
после правок в админке обновляются без сборки. Манифест использует актуальное имя.

## Редактор по референсу

Две отдельные панели: тексты и изображение. Текстовая форма содержит title,
meta description, OG title/description и отдельное schema_description. Вторая —
текущий снимок, загрузку и image_alt («Что на картинке»). POST section_part=texts
или preview проверяет только соответствующие поля, остальные значения сохраняет.
Полный POST остаётся поддержан для совместимости. Пустое schema_description
использует meta description; пустое image_alt — OG title. Эти новые поля не делают
старые копии БД недействительными. Произвольные подстановки из примера не внедрены:
по согласованному решению свободные тексты редактируются вручную.

Пять текстовых полей имеют SSR-счётчики и подсказки длины; admin-character-count.js
обновляет длину по вводу, Unicode-символы считаются как mb_strlen на сервере.
60/160/200 — ориентиры краткости, не обещание определённого вида поисковой выдачи.
Админка сохраняет кофейную палитру, из референса взята структура.

Для OG принимается исходник от 1200×630, до 10 МБ, JPG/PNG/WebP. Сохраняются JPG
1200×630 и WebP 600×315 / 1200×630 для retina-просмотра. Старый JPEG без миниатюр
показывается напрямую, поэтому прежние данные не ломаются. Исходные миниатюры
og-image.webp и og-image@2x.webp генерирует build-og-image.php вместе с JPG.
Пользовательские файлы включаются в полную копию, исходные — в дистрибутив.
