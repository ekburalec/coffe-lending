# SQLite: схема v1

`schema_version` — версия миграции; импорт только на пустой базе.
`records` — типизированные коллекции: составной ключ kind/id, JSON payload,
целый sort_order, visible 0/1. Типы: categories, products, navigation, hours,
exceptions, content, images, faq, announcements, reviews. Связь products.category
проверяется серверным валидатором; удаление занятой категории запрещено.
`settings` — именованные группы contacts, delivery, seo, rating с JSON payload.
`admins` — единственная запись id=1, username и password_hash.
`login_attempts` — хеш IP, число ошибок, начало окна ограничения.

Доступ только через PDO prepared statements. Обычные строки JSON экранируются.
records.content имеет необязательный format: text (по умолчанию) либо inline.
Только inline интерпретирует text как очищенный HTML strong/em/br без атрибутов.
Таблицы и журнал схемы не меняются; версия редактора вычисляется из полной записи.
Миграция: `php bin/migrate.php`; seed.json — исходная демо-редакция, не рабочая БД.
Конкурентные записи сериализует SQLite, busy_timeout 5 секунд. Файлы в APP_DATA_DIR.

При повторной миграции отсутствующие фиксированные поля content/images/hours
добавляются из seed без перезаписи имеющихся значений. Каталог и настройки не
пересеиваются; это позволяет обновлять шаблон с новыми фиксированными полями.

Миграция данных 2 однократно добавляет/показывает пункт «Отзывы» → #reviews.
Физическая схема остаётся v1, schema_version хранит журнал [1, 2]. Повторные
запуски не возвращают удалённую ссылку и не отменяют последующее редактирование.
Копии со старым журналом [1] остаются допустимыми; после обновления запускайте migrate.

settings.seo дополнен необязательными schema_description и image_alt. Пустые или
отсутствующие значения используют description/og_title. Новых таблиц нет.


records.reviews дополнен необязательными image/alt и is_demo (0 для старых записей).
Это поля JSON без новой таблицы или версии схемы. is_demo=1 разрешает отсутствие
источника и всегда включает публичную подпись о вымышленных данных. Импорт примеров
осуществляется отдельной CLI-командой, обычная миграция их не создаёт.


Ранее settings.contacts был дополнен необязательными vk_url, ok_url, telegram_url,
whatsapp_url, rutube_url. Отсутствующие или пустые строки дают ссылки-заглушки.
Новых таблиц/версий схемы нет; HTTP(S) валидируется при редактировании и восстановлении.


По новому решению пользователя соцсети вынесены в settings.social (необязательная
группа JSON): пять наборов {vk,ok,telegram,whatsapp,rutube}_{name,label,url}.
При отсутствии значений используются начальные названия/подписи и прежние URL
из contacts. Отдельное сохранение social имеет приоритет, включая пустой URL.
Группа необязательна для старых резервных копий; новая группа валидируется по
config/admin.php. Старые контакты проверяются на безопасность URL при восстановлении.
Миграция таблиц и изменение журнала schema_version не нужны.

settings.social дополнен необязательными {key}_visible (0/1). Отсутствующее поле
означает 1 для совместимости со старыми настройками и копиями. Скрытие не удаляет
название, подпись и URL. Новых таблиц и версии схемы нет.

В seed добавлены space-fact-1/2/3 и reviews-title. Их отсутствие в старой БД/копии
допустимо: вывод подхватывает seed, migrate добавляет отсутствующее. Остальные
обязательные записи проверяются как прежде. inline в копиях должен точно
соответствовать очищенному HTML. Подробнее: ../modules/visual-editor.md.


## Фаза заказов: миграция 3

config/orders-schema.sql добавляет orders, order_items, order_events,
order_mail_queue и order_attempts; журнал становится [1,2,3]. Все существующие
записи контента сохраняются. Две новые категории создаются без товаров.
Только узнаваемые исходные тексты об отсутствии оформления и демо-тариф
150 ₽ / радиус 3 км обновляются на новые; пользовательские тексты не заменяются.

orders хранит снимки контактов/тарифа, суммы в целых рублях, способ, статус,
желаемое/согласованное время, завершение, версию и ключ идемпотентности.
order_items не зависит внешним ключом от каталога, удаление товара сохраняет заказ.
order_events содержит автора/время и изменения состава/статуса без копирования контактов.
order_mail_queue ссылается на заказ, не дублирует получателя и тело письма.
order_attempts хранит только хеш IP и часовой счётчик попыток.

APP_DATA_DIR/order-erasure.json содержит хеши случайных токенов обезличенных
заказов. Файл не заменяется восстановлением БД, поэтому старая копия не может
вернуть удалённые контакты. Сохраняйте его при переносе приватного каталога.
APP_DATA_DIR/smtp.json содержит секреты SMTP, не входит в экспорт БД/ZIP.
Системная настройка SQLite secure_delete включена.
