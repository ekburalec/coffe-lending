# Авторизация администратора

После `php bin/migrate.php` создать пользователя: новый пароль 15–128 символов передать через
stdin в `php bin/create-admin.php LOGIN`. Пароля по умолчанию нет. --reset явно
сбрасывает пароль и удаляет прежние сессии. Не сохранять пароль в репозитории.
/admin/login — GET/POST, /admin/logout — только POST с CSRF. Сессия HttpOnly,
SameSite=Strict, Secure при HTTPS, простаивает максимум 30 минут. ID и CSRF меняются
при входе. Пять неудач за 15 минут блокируют IP на остаток окна, proxy-заголовки не
используются. Все страницы админки no-store/noindex. После входа открывается
сам сайт с верхней панелью редактора. Cookie имеет Path=/; при запросе к админке
прежняя cookie Path=/admin переносится на / с тем же ID и удаляется из старой
области. Сайт проверяет существующую сессию, включая таймаут и отзыв по паролю.
Гость без cookie не создаёт сессию. HTML с панелью — no-store/noindex, Vary: Cookie.
Проверки: tests/integration.py и tests/visual-editor-http.py.

## Смена пароля в админке

Пункт «Пароль» в боковом меню и на главной ведёт на
GET/POST /admin/password. Доступ только после входа. POST требует текущий CSRF,
текущий пароль, новый и его подтверждение. Новый пароль — 15–128 Unicode-символов
без NUL, до 512 байт; на PHP без Argon2id предел 72 байта с явной ошибкой,
должен отличаться от текущего; пробелы не обрезаются. Подтверждение сравнивается
с исходной строкой. Неверный текущий пароль учитывается отдельным ключом IP
в существующем login_attempts: пять ошибок за 15 минут блокируют только смену
пароля (429), вход остаётся независимым. Ошибки формы — 422, CSRF — 403.

app/services/auth.php проверяет пароль через password_verify, создаёт хеш через
hashAdminPassword (Argon2id, 19456 KiB, time_cost=2, threads=1;
при недоступности алгоритма bcrypt с пределом 72 байта). app/models/auth.php обновляет только password_hash
с проверкой прежнего хеша. Нет изменения логина, таблиц или публичных данных.
Конфликт обновления — 409. После успеха: новый ID сессии и CSRF, redirect на форму
с сообщением «Пароль изменён». Пароли не возвращаются в HTML и не сохраняются открыто.
Шаблон templates/admin/password.tpl использует существующие классы админки,
label, autocomplete=current-password/new-password, aria-invalid и связанные ошибки.
Основная форма работает без JavaScript, с клавиатуры и от 320 px.

Страница называется «Пароль» и поясняет, что новый пароль действует после
сохранения, а сохранённый хеш нельзя посмотреть как исходный пароль.
Плашка показывает экранированный актуальный логин из аккаунта, без поля изменения.
Для смены логина указана существующая CLI-команда
`php bin/create-admin.php НОВЫЙ_ЛОГИН --reset` с новым паролем через stdin;
она также сбрасывает пароль. Оформление использует прежние классы и палитру админки.

В сессии хранится SHA-256 отпечаток текущего хеша password_hash. Каждый запрос
админки и авторизованного лендинга сверяет его с аккаунтом. Текущая сессия получает новый отпечаток после
смены; остальные сбрасываются при следующем запросе. Прежние сессии без отпечатка
после обновления требуют однократного повторного входа. Сброс через CLI и
восстановление аккаунта из копии также не оставляют сессии со старым отпечатком.

tests/integration.py проверяет доступ без входа, CSRF, неверный текущий пароль,
подтверждение, длины/массив/NUL, неизменность хеша при ошибках, успешную смену,
ротацию ID/CSRF, отзыв второй сессии, вход новым паролем, отказ старому, сохранение
пробелов и границу 72 байта, независимое ограничение попыток. Все данные тестовые.
Вход и проверка текущего пароля учитывают алгоритм сохранённого хеша: bcrypt
ограничен 72 байтами, Argon2id 512 байтами. Длинная строка с совпадающими первыми
72 байтами не должна приниматься за bcrypt-пароль. Минимум нового пароля
не применяется к входу по прежнему хешу; автоматического перехеширования при входе нет.
Хеш обновляется только при явной смене/CLI-сбросе, поэтому обычный вход не отзывает
другие сеансы. Пароли не обрезаются и не нормализуются при проверке.

## Политика новых паролей

Общая политика `app/services/passwords.php` и `config/passwords.php` применяется
к форме и CLI. Длина считается в Unicode code points, а не байтах или UTF-16.
Локальный список слабых полных значений и ожидаемых производных логина
проверяется без учёта регистра; хешируется исходная строка с пробелами.
Это небольшой локальный список, не полная база утечек. Периодической смены и
обязательного сочетания категорий для ручного пароля нет. Параметры Argon2id
проверяются на целевом хостинге перед публикацией; локальный замер около 29 ms.
Необязательная серверная проверка HIBP после остальных проверок включается
через APP_PASSWORD_HIBP=1. По умолчанию отключена; на форме явно показан статус.
Сбой сервиса не меняет пароль. Подробности: ../integrations/pwned-passwords.md.
tests/admin-password-browser.cjs проверяет меню, клавиатуру, связанные ошибки,
autocomplete, отсутствие паролей в полях после ошибки и ширины 320/768/1440 px.


## Генератор и показ паролей

Доступны два режима: случайные символы и парольная фраза из локального словаря
EFF Long Wordlist (7776 уникальных слов). Фраза по умолчанию из 7 слов,
допустимо 6–8, разделитель пробел. Четыре слова словаря содержат внутренний
дефис; слова/порядок словаря не менялись, лицензия CC BY 4.0 в licenses/.
Каждый индекс выбирается через Uint16Array с отбрасыванием значений >=62208,
без смещения вероятностей. Повторы слов допустимы. Длина не подгоняется
обрезанием: допустимое число слов рассчитывается по максимальной длине слова
9 и серверному пределу байт (при bcrypt не больше 7 слов). Фильтры символов
в режиме фразы скрыты и не применяются. Словарь password-words.js является
модулем данных, включается собственным сборщиком через статический импорт;
генерация не обращается к EFF или другим внешним сервисам.

admin-password-controls.js добавляет глазик во вход и три поля смены пароля.
Кнопки type=button, aria-controls/pressed и доступные подписи переключаются вместе
с input.type и SVG-иконкой. Перед отправкой форма снова скрывает пароли.
На странице входа генератора нет: случайная строка не является паролем аккаунта.
Автозаполнение current-password/new-password сохранено для менеджеров паролей.

«Сгенерировать пароль» предлагает 20 ASCII-символов по умолчанию, длина
настраивается от 16 до 64. Исходный алфавит: A–Z, a–z, 0–9, дефис и подчёркивание.
Подсказки различают общие «Требования к новому паролю» и «Длину в генераторе»:
15–128 относится к сохранению, 16–64 только к выбору длины случайных символов.
Подпись поля: «Длина генерируемого пароля». Диапазоны проверки и генерации не менялись.
Символы 0/O/o/1/I/l исключаются всегда, в том числе после пользовательских
настроек. Флажка или другого способа включить их в символьную генерацию нет.
Индекс выбирается через crypto.getRandomValues с отбрасыванием байтов за порогом
floor(256/N)*N: каждый разрешённый символ равновероятен при любом размере алфавита.
Math.random не используется. Ошибка API или настроек не затирает введённый пароль.
Без криптографического API генерация отключена с пояснением, ручная смена доступна.

«Дополнительные настройки» раскрывают группы a–z/A–Z/0–9/знаки, произвольные
исключения и собственную пунктуацию с английской раскладки (без пробелов).
Группы включены по умолчанию, собственные знаки по умолчанию `-_`.
Алфавит очищается от дубликатов и исключений; отсутствие групп, менее двух
символов или опустевшая включённая группа дают ошибку без замены ввода.
Включение группы разрешает её символы, но не требует их присутствия.
Отдельный флажок гарантирует минимум один знак каждой выбранной группы:
равномерно выбранные целые строки отбрасываются до выполнения условия,
максимум 256 кандидатов, затем понятная ошибка без потери ввода.
Если верхняя оценка пространства L*log2(N) меньше 80 бит, показывается совет
увеличить длину или набор; это внутренняя подсказка, не правило NIST и не оценка
ручного пароля. Точное время взлома не показывается.

Настройки применяются только по нажатию генерации. Они не ограничивают ручной
пароль и не участвуют в проверке формы смены; поля связаны с отдельной формой
настроек без отправки. Генерация заполняет новый пароль и подтверждение,
не отправляет форму, не меняет текущий пароль и снова скрывает оба новых поля.
Пароль остаётся скрытым до нажатия глазика. «Скопировать» записывает значение
в буфер только по нажатию; при отказе появляется пояснение ручного копирования.
Ни хранилища браузера, ни логи для паролей не используются. Реальное изменение
происходит после текущего пароля и кнопки «Изменить пароль».

Без JS глазики и генератор скрыты, обычный вход и ручная смена продолжают работать.
admin.js подключён и на странице входа, модули защищены от отсутствующих элементов.
CSS-блок password-control использует токены vars.css и прежнюю кофейную палитру.
Проверки: tests/admin-password-controls-browser.cjs на изолированном аккаунте:
генерация/подтверждение, повторная генерация, буфер (имитирован, системный не меняется),
глазики/клавиатура, отсутствие POST до сохранения, no-JS и 320/768/1440.
Рабочий пароль в ходе реализации не менялся.

tests/admin-password-accessibility-browser.cjs проверяет раскрытие настроек
клавиатурой, видимый фокус, label/описания/уникальные ID, отдельную принадлежность
полей форме настроек, раскрытый адаптив 320/768/1440 и наследование тёмных токенов.

В нижней группе меню «Пароль» и «Визуальный редактор» разделены бордером:
горизонтальным на desktop и вертикальным в мобильной полосе навигации.

## Индикатор надёжности

admin-password-strength.js добавляет только локальную ориентировочную оценку
нового пароля: четыре сегмента и подпись «Оценка: Слабый / Средний / Надёжный /
Отличный». Пустое поле даёт пустую полоску и «Введите пароль».
Высота 6 px, ширина поля, зазор сегментов 4 px, отступ от поля 8 px задаётся
существующим gap формы. Подпись 13 px; медный акцент, фон линии и тёмные токены
взяты из текущей палитры. Индикатор не добавляет красную/жёлтую/зелёную схему.
role=meter, aria-valuenow/valuetext и связанная текстовая подпись не полагаются
на цвет. Без JS индикатор скрыт, ручная смена остаётся рабочей.

Для ручного ввода проверяются длина в Unicode code points, разнообразие,
очевидные повторы, последовательности и небольшой набор известных слабых
значений. Это эвристика без оценки битов или времени взлома; максимум
«Надёжный». Она не является проверкой утечек и не меняет серверную валидацию.
Для результата генератора используются параметры выбора: L*log2(N) для символов,
W*log2(7776) для слов. При обязательных категориях используется консервативная
нижняя граница (L-k)*log2(N)+sum(log2(размер группы)). Группы не пересекаются.
Уровни по этой оценке: менее 50 бит слабый, менее 70 средний, менее 100 надёжный,
от 100 отличный; очевидно повторяющийся/слабый результат остаётся слабым.
Это внутренние уровни интерфейса, не нормативные пороги NIST.

Генератор сообщает модулю только числовую оценку событием password-generated,
без пароля в detail. Ручной input/change сбрасывает эту оценку. Смена настроек
не пересчитывает индикатор уже введённого пароля. Показ/скрытие не меняет уровень.
Оценка не обращается к сети, не хранит пароль и не выводит его в статус/логи.

Проверка: tests/admin-password-strength-browser.cjs. Сценарий проверяет уровни,
повторы/последовательности, генерацию и фразы, маленький алфавит при большой длине,
сброс/редактирование, ARIA и размеры 6/4/8/13 px на 320/768/1440, наследование
цветов светлой/тёмной темы и отсутствие запросов. Прежние сценарии генератора
обновлены: флажка нет, автоматическое исключение действует всегда.
