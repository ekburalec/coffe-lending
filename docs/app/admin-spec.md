# Админка: согласованная спецификация

## Решение и границы
PHP-сайт и /admin на одном хостинге; SQLite через PDO, PHP 8.2+, MVC на функциях,
шаблоны .tpl. Один администратор создаётся только CLI. Сохранение сразу публикует
данные. CSS/JS остаются нативными. По решению пользователя добавляются заказы и контакты для получения по ../product/logic/orders.md.
Онлайн-оплата, метки товаров и универсальный конструктор страниц исключены.

## Данные
- Категории: название, порядок, видимость. Нельзя удалить категорию с товарами.
- Товар: стабильный ID, категория, название, описание, состав, порция, целая цена
  в рублях, фото/alt, порядок, видимость, наличие. Скрытый не выводится; отсутствующий
  виден без добавления. Архивирование — скрытие, удаление отдельно и явно.
- Контакты: название, город, улица, телефон, реальная ссылка карты (не задана по умолчанию).
- Соцсети: отдельный пункт, пять полных названий, двухбуквенные латинские подписи
  и необязательные HTTP(S)-URL. У каждой сети есть «Показывать на сайте»:
  отключение скрывает ссылку, сохраняя название, подпись и URL. Пустой адрес даёт
  заглушку; прежние URL сохраняются. Если отключены все сети, блок соцсетей скрыт.
  На лендинге вместо букв используются локальные SVG-иконки по ключу сети;
  прежние короткие подписи сохраняются для совместимости данных.
- График: по дням недели, закрытые дни; исключение на конкретную дату выше обычного
  графика. Время и даты — Asia/Yekaterinburg; ночные интервалы в первой версии не поддержаны.
- Получение: включение самовывоза/доставки, целые рубли тарифа/порога, зона и сроки.
  Нельзя отключить оба способа. Пустая корзина — нулевая доставка; порог включительно.
- Контент: тексты и фотографии существующих блоков, подписи CTA и alt; структура
  секций остаётся заданной шаблоном. Старые тексты остаются обычным текстом.
  По решению пользователя визуальный редактор разрешает strong/em/br для фиксированных
  текстов, alt и замену фото самостоятельных блоков. Общие сохранение/отмена, счётчик,
  верхняя панель непосредственно на сайте после входа, без отдельной страницы
  и iframe. Кнопка «Редактор сайта» переключает правку/просмотр; используется
  реальная ширина окна. Структурированные данные исключены.
  Подробности: ../modules/visual-editor.md и ../product/logic/visual-editor.md.
- Навигация: подпись, существующий якорь из белого списка, порядок перетаскиванием, видимость.
- FAQ: вопрос, ответ, порядок перетаскиванием, видимость. Служебные ответы о графике и доставке
  формируются из настроек; свободные упоминания администратор обновляет вручную.
- Объявления: текст, включение, начало/окончание включительно по локальному времени.
- Отзывы: автор, текст, фото/alt (необязательно), статус демо, порядок, видимость.
  Для реальных отзывов источник обязателен. По поручению пользователя доступны
  три сгенерированных демо-примера с явной подписью о вымышленных тексте/авторе и фото.
  Демо-примеры не участвуют в рейтинге. Пустой раздел видим с сообщением «Отзывов пока нет».
  Рейтинг: значение, количество, URL источника; без источника не публикуется.
- SEO: title, description, OG title/description, отдельное описание schema.org,
  превью JPG с alt, просмотр изображения и счётчики символов. JSON-LD создаётся из
  контактов, графика, каталога, видимых FAQ; не редактируется произвольным JSON.

## Единый источник
После миграции SQLite — источник рабочего контента. product.md и landing-content.md
описывают начальные демо-данные и редакционную основу, не переписывают БД при запуске.
Каталог питает карточки и строки корзины. Контакты/график/доставка питают подвал,
первый экран, бегущую строку, служебные FAQ и JSON-LD. SEO с ценой выводит актуальную
минимальную цену отдельно от свободного description. Произвольных подстановок нет.

## Безопасность и хранение
Все изменения POST + CSRF, серверная валидация, экранирование вывода, PDO-параметры.
Раздел «Пароль» позволяет сменить пароль после проверки текущего
и подтверждения нового (15–128 Unicode-символов, до 512 байт, без NUL;
при bcrypt предел 72 байта). Новые хеши Argon2id при наличии в PHP,
локальная проверка слабых значений едина для формы и CLI. Прежний вход
совместим с bcrypt и не применяет новый минимум к существующему паролю.
Смена обновляет ID/CSRF текущей сессии,
остальные сеансы теряют доступ. Старые сеансы без отпечатка пароля требуют нового
входа после обновления. Подробности и ограничение попыток: ../modules/admin-auth.md.
Сессии HttpOnly/SameSite, Secure по HTTPS, таймаут, обновление ID после входа.
Ограничение попыток по IP с хранением в SQLite; доверять X-Forwarded-For нельзя.
SQLite, логи, копии и сессии в приватном каталоге вне публичного корня на хостинге.
Загрузки только растровые, MIME/размер/пиксели проверяются, имена случайные.
Резервная копия БД и полный ZIP с изображениями; восстановление проверяет формат,
схему и пути, требует явного подтверждения и создаёт предварительную полную копию.
Автокопии показываются отдельно, хранятся последние пять; ручные архивы сохраняются.

## Приёмка
Редактирование каждого типа отражается на странице, меню читается без JS.
Корзина передаёт состав на серверное оформление; заказ получает номер после сохранения.
Особые даты, пустые коллекции, скрытые категории и границы доставки проверены.
Установка не содержит известного пароля; повторная миграция сохраняет правки.
Обновление приложения не заменяет рабочую БД/загрузки. Копия восстанавливается
в изолированном окружении. Проверки и ограничения записываются в ADMIN-PLAN.md.

Пароль администратора можно сгенерировать локально в браузере (20 символов
по умолчанию, длина 16–64), скопировать и показать/скрыть. Всегда исключаются
похожие символы 0/O/o/1/I/l, без флажка и возможности вернуть их. Настройки не меняют
введённый пароль до нажатия генерации; результат снова скрывает оба новых поля.
Случайный выбор равномерный для изменяемого алфавита, без сетевых запросов.
Дополнительные настройки: разрешённые группы, собственные знаки, исключения
и необязательная гарантия каждой группы; недопустимые сочетания дают понятную ошибку.
Второй режим: парольная фраза из 6–8 случайных слов локального словаря EFF
с пробелами, по умолчанию 7; серверный предел учитывается без обрезания результата.
Под новым паролем ориентировочная оценка: четыре сегмента 6 px с зазором 4 px,
ширина поля, отступ 8 px, подпись 13 px. Используется текущая кофейная палитра.
Оценка локальная и не влияет на серверные правила или HIBP.
Предложение не меняет пароль без текущего пароля
и явного сохранения; при входе доступен только показ/скрытие.

«Пароль» и «Визуальный редактор» образуют отдельную нижнюю группу меню, редактор
сразу после пароля и ведёт на сайт в текущей вкладке. После входа открывается
сайт с верхней панелью; гость её не видит. Общий пакет текста/фото сохраняется атомарно с проверкой версий.

По поручению пользователя «Пароль» отделён от «Визуального редактора» бордером
внутри нижней группы; в мобильной горизонтальной навигации разделитель вертикальный.
