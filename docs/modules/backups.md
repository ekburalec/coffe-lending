# Резервные копии и восстановление

/admin/backups: экспорт SQLite через VACUUM INTO (согласованный снимок), полный ZIP,
скачивание сохранённых копий, восстановление .sqlite/.zip. Только авторизованный
POST с CSRF. ZIP содержит site.sqlite, manifest.json с SHA-256 и media/ с загруженными
фотографиями; исходные картинки/иконки/шрифты поставляются с версией приложения.
Копии включают аккаунт администратора. Не публиковать их и не помещать в git.

Восстановление требует галочки. Проверяются размер (загрузка до 200 МБ, реальный
лимит PHP может быть ниже), число записей/суммарный размер ZIP, пути, отсутствие
повторов, манифест/хеши, MIME фотографий, определения таблиц и версия SQLite,
целостность БД, обязательные поля, ссылки, категории, расписание и наличие медиа.
ZIP не распаковывается через extractTo. Нет исполнения SQL из загруженного текста.
Перед заменой автоматически создаётся полный архив текущего состояния. Имена медиа
неизменяемы: конфликт содержимого под одним именем отклоняется. Копия БД без медиа
восстанавливается только если нужные фото уже доступны на сервере.

Все HTTP-запросы держат application.lock (GET shared, POST exclusive). Миграция и
смена администратора держат exclusive. Поэтому замена БД не пересекается с записью
или чтением. БД закрывается перед заменой; при ошибке rename возвращается предыдущая.
Сессии отзываются после успеха, вход с аккаунтом из копии. APP_DATA_DIR/backups —
приватное хранилище. Ручные копии не удаляются автоматически; следите за свободным местом
и сохраняйте внешние копии. Для крупного каталога лимиты архива нужно пересмотреть.

tests/integration.py проверяет экспорт SQLite/ZIP, отказ для неверной БД и ZIP с ../,
восстановление после изменения адреса и удаления загруженных фото, автоматическую
предварительную копию и отзыв сессии. Рабочие файлы не затрагиваются.

## Автокопии по референсу

Четыре отдельные панели: экспорт, восстановление, автокопии, ручные архивы.
Кофейная палитра сохранена. Перед восстановлением создаётся полный ZIP с префиксом
`auto-backup-`; хранятся пять последних, текущая предварительная копия защищена
от удаления. Очистка касается только этого префикса и выполняется до замены БД.
Если очистка/сохранение недоступны, восстановление прекращается с сообщением.
Ручные backup-* остаются отдельно. Старые архивы с этим префиксом не переименовываются.
Список показывает местное время, размер и кнопку скачивания POST+CSRF. Для возврата
нужно скачать архив и загрузить в форму восстановления. Без автокопий виден честный
пустой блок. HTTP-тесты проверяют ограничение пятью, сохранность ручного архива,
скачивание и отклонение обхода пути. Адаптив 320/768/1440 проверен в браузере.

Визуальный редактор: необязательный format=text/inline в content, inline строго
проверяется по strong/em/br без атрибутов. Старые копии допускают отсутствие только
четырёх новых ключей space-fact-1/2/3 и reviews-title; вывод подхватывает seed до
migrate. Остальные проверки обязательных записей сохранены.


## Копии с заказами

Допускаются старая схема и новая с таблицами заказов. Проверяются определения,
внешние ключи, контакты, допустимые статусы и суммы строк. При наличии заказов
нужно отдельное подтверждение полного отката. После замены создаются отсутствующие
таблицы, очищается очередь писем, применяется обезличивание с приватным реестром.
Копии с персональными данными старше двух месяцев удаляются ежедневной CLI-задачей.
Архивы без персональных данных не затрагиваются. Внешние скачанные копии удаляет
владелец. Перенос SMTP и реестра обезличивания выполняется отдельно вместе с
приватным каталогом; экспорт ZIP содержит только БД и фотографии.
