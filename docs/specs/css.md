# Стиль кода — CSS

## Зачем

Этот файл задаёт правила CSS в проекте.
Цель — простые, предсказуемые, поддерживаемые и единообразные стили как при ручной разработке, так и при разработке с ИИ.

## Стек

- Только чистый CSS
- Именование по BEM
- CSS-импорты
- Без SCSS / Sass / Less
- Без Tailwind
- Без CSS-in-JS
- Без CSS-фреймворков интерфейса
- Без inline-стилей, кроме редких технических случаев

## Структура CSS

Все стили лежат в:

`assets/css/`

Структура:

- `base/`
    - `vars.css` — переменные
    - `reset.css` — сброс стилей
    - `base.css` — глобальные базовые стили
- `blocks/` — переиспользуемые блоки интерфейса
- `sections/` — секции страниц
- `utils/` — редкие утилитарные классы, только если без них никак

## Точка входа и сборка

`assets/css/main.css` — единственный CSS, который подключает страница. В нём только
`@import` файлов в порядке ниже. При разработке браузер грузит цепочку `@import` как есть;
для хостинга `php bin/build-dist.php` встраивает все `@import` в один файл, переписывает
относительные `url()`, вырезает комментарии и подключает результат с хэшем `?v=`
(`docs/specs/deploy.md`).

- Новый CSS-файл подключается только через `@import url('./…');` в `main.css`
- `@import` с медиа-условием, абсолютные пути в `@import` и пути за пределами проекта —
  ошибка сборки
- Шрифты подключаются `@font-face` в `base/base.css` из `assets/fonts/` (woff2), критичные
  для первого экрана — ещё и `<link rel="preload">` в `<head>`

## Порядок импорта

1. vars
2. reset
3. base
4. blocks
5. sections
6. utils

## Именование

Только BEM:

- `block`
- `block__element`
- `block--modifier`

Правила:

- только строчные буквы
- слова разделяются дефисом
- имя класса описывает смысл, а не внешний вид
- никаких случайных сокращений
- никаких id для стилизации

## Файлы

- Один файл — одна ответственность
- Один блок — один файл
- Одна секция — один файл
- Не смешивай в одном файле несвязанные стили

## Правила CSS

- Селекторы — простые
- Предпочтительно — селекторы по классу
- Избегай глубокой вложенности
- Избегай высокой специфичности
- Избегай глобальных побочных эффектов
- Не стилизуй через цепочки тегов
- Не собирай раскладку хаками, если задачу решает flex/grid

## Переменные

Переменные CSS из `vars.css` используются для:

- цветов
- отступов
- шрифтов
- скруглений
- теней
- ширины контейнеров
- переходов
- брейкпоинтов, если нужно

Не разбрасывай по проекту «сырые» значения без причины.

## Раскладка

Используем:

- flex
- grid
- обычный поток документа

Не усложняй раскладку.

## Адаптивность

Адаптивная вёрстка обязательна.

Используй небольшой фиксированный набор брейкпоинтов, заданный в проекте.
Медиа-запросы держатся рядом с блоком или секцией, к которой относятся, а не в отдельных хаотичных файлах.

## Формы

Элементы форм оформляются единообразно:

- input
- textarea
- select
- button
- label
- сообщение об ошибке
- подсказка

Состояния должны быть явными:

- hover
- focus
- active
- disabled
- error
- success
- loading

## Изображения и иконки

- Растровые изображения: webp с retina-версией `@2x` (см. `docs/specs/html.md` и `docs/design/images.md`); картинка превью ссылки — jpg
- Векторная графика и иконки: svg
- Изображения адаптивные
- Пропорции сохраняются, если их не меняют намеренно

## Правила для ИИ

ИИ обязан:

- следовать этой структуре CSS
- использовать только BEM
- использовать существующие переменные
- класть стили в правильные папки
- держать адаптивные правила рядом со связанными стилями

ИИ запрещено:

- вводить новые технологии стилизации
- переписывать весь CSS ради мелких правок
- смешивать в одном файле несвязанные стили
- нарушать правила именования
- плодить хаотичные утилитарные классы
- повышать специфичность без необходимости

## Definition of Done

CSS готов, когда:

- файлы лежат в правильных папках
- именование соответствует BEM
- стили читаемы и поддерживаемы
- переменные используются последовательно
- адаптивность реализована
- блоки изолированы
- нет хаотичных переопределений
- результат соответствует дизайн-направлению проекта
