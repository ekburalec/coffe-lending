# Резервные копии и восстановление

/admin/backups: экспорт SQLite через VACUUM INTO (согласованный снимок), полный ZIP,
скачивание сохранённых копий, восстановление .sqlite/.zip. Только авторизованный
POST с CSRF. ZIP содержит site.sqlite, manifest.json с SHA-256 и media/ с загруженными
фотографиями; исходные картинки/иконки/шрифты поставляются с версией приложения.
Копии включают аккаунт администратора. Не публиковать их и не помещать в git.

Восстановление требует галочки. Проверяются размер (загрузка до 200 МБ, реальный
лимит PHP может быть ниже), число записей/суммарный размер ZIP, пути, отсутствие
повторов, манифест/хеши, MIME фотографий, определения таблиц и версия SQLite,
целостность БД, обязательные поля, ссылки, категории, расписание и наличие медиа.
ZIP не распаковывается через extractTo. Нет исполнения SQL из загруженного текста.
Перед заменой автоматически создаётся полный архив текущего состояния. Имена медиа
неизменяемы: конфликт содержимого под одним именем отклоняется. Копия БД без медиа
восстанавливается только если нужные фото уже доступны на сервере.

Все HTTP-запросы держат application.lock (GET shared, POST exclusive). Миграция и
смена администратора держат exclusive. Поэтому замена БД не пересекается с записью
или чтением. БД закрывается перед заменой; при ошибке rename возвращается предыдущая.
Сессии отзываются после успеха, вход с аккаунтом из копии. APP_DATA_DIR/backups —
приватное хранилище. Копии не удаляются автоматически; следите за свободным местом
и сохраняйте внешние копии. Для крупного каталога лимиты архива нужно пересмотреть.

tests/integration.py проверяет экспорт SQLite/ZIP, отказ для неверной БД и ZIP с ../,
восстановление после изменения адреса и удаления загруженных фото, автоматическую
предварительную копию и отзыв сессии. Рабочие файлы не затрагиваются.
