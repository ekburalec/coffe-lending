# Стиль кода — HTML

## Назначение

Этот файл задаёт правила HTML в проекте.
Цель — семантичная, доступная, читаемая и единообразная разметка, кто бы её ни писал: человек вручную или ИИ.

## Стек

- Только HTML5
- Семантические теги там, где они уместны
- ARIA-атрибуты там, где нативной семантики не хватает
- Никаких HTML-фреймворков и библиотек компонентов
- Никаких inline-стилей
- Никакого inline JavaScript (обработчиков событий в атрибутах)
- Никаких устаревших тегов (`<font>`, `<center>`, `<b>`, `<i>` для семантики и т. п.)

---

## Структура документа

Каждая HTML-страница начинается с правильного объявления и набора meta:

```html
<!DOCTYPE html>
<html lang="ru">
	<head>
		<meta charset="UTF-8" />
		<meta name="viewport" content="width=device-width, initial-scale=1.0" />
		<meta name="description" content="..." />
		<title>Page Title — Site Name</title>
		<link rel="stylesheet" href="/assets/css/main.css" />
	</head>
	<body>
		...
	</body>
</html>
```

Правила:

- Атрибут `lang` на `<html>` обязателен и всегда совпадает с языком контента
- `charset` — только `UTF-8`
- meta `viewport` обязателен на каждой странице
- meta `description` обязателен на каждой странице
- `<title>` уникален для каждой страницы и описывает её
- CSS подключается в `<head>`, JS — перед `</body>` или с `defer`

## Семантическая структура

Семантические элементы HTML5 описывают смысл контента, а не его внешний вид.

### Каркас страницы

```html
<header>
	<!-- шапка сайта: логотип, навигация -->
	<nav>
		<!-- блок навигации -->
		<main>
			<!-- основной уникальный контент страницы (один на страницу) -->
			<aside>
				<!-- боковая колонка, связанный контент -->
				<footer>
					<!-- подвал сайта или раздела -->
					<section>
						<!-- тематический раздел с заголовком -->
						<article>
							<!-- самостоятельный независимый контент (запись, карточка, комментарий) -->
						</article>
					</section>
				</footer>
			</aside>
		</main>
	</nav>
</header>
```

Правила:

- Один `<main>` на страницу
- `<header>` и `<footer>` могут стоять внутри `<article>` и `<section>`
- У `<section>` обязательно есть заголовок (`<h1>`–`<h6>`)
- `<article>` — для контента, который имеет смысл сам по себе (запись, комментарий, карточка)
- `<nav>` — для основных и второстепенных блоков навигации
- `<aside>` — для контента, связанного с основным, но отделённого от него

### Заголовки

- Заголовки идут в логическом порядке: `<h1>` → `<h2>` → `<h3>` и т. д.
- Уровни заголовков не пропускаем
- Один `<h1>` на страницу — главная тема страницы
- Заголовки не используем ради оформления — для этого есть CSS-классы

### Текстовый контент

```html
<p><!-- абзац --></p>
<ul>
	/
	<ol>
		<!-- списки -->
		<li>
			<!-- элемент списка -->
			<dl>
				<!-- список определений -->
				<dt>/</dt>
				<dd>
					<!-- термин / описание -->
					<blockquote>
						<!-- длинная цитата из внешнего источника -->
						<cite>
							<!-- ссылка на источник -->
							<time>
								<!-- дата или время -->
								<address>
									<!-- контактная информация -->
									<strong>
										<!-- важный текст (семантический жирный) -->
										<em>
											<!-- выделенный текст (семантический курсив) -->
											<code>
												<!-- код в строке -->
												<pre>>
											</code></em
										></strong
									>
								</address></time
							></cite
						>
					</blockquote>
				</dd>
			</dl>
		</li>
	</ol>
</ul>
```

`<b>` и `<i>` для семантики не используем — для этого есть `<strong>` и `<em>`.
`<b>` и `<i>` — только когда смысловой нагрузки нет и нужно лишь оформление.

## Формы

### Структура

```html
<form action="/submit" method="post" novalidate>
	<fieldset>
		<legend>Group title</legend>

		<div class="form__field">
			<label for="email">Email</label>
			<input
				type="email"
				id="email"
				name="email"
				autocomplete="email"
				required
				aria-describedby="email-hint email-error"
			/>
			<span id="email-hint" class="form__hint"
				>We'll never share your email.</span
			>
			<span
				id="email-error"
				class="form__error"
				role="alert"
				aria-live="polite"
			></span>
		</div>
	</fieldset>
	<button type="submit">Submit</button>
</form>
```

Правила:

- У каждого `<input>`, `<select>`, `<textarea>` есть парный `<label>` через `for` + `id`
- placeholder никогда не заменяет `<label>`
- Атрибут `autocomplete` указывается везде, где он применим
- Связанные поля группируются в `<fieldset>` с `<legend>`
- Сообщения об ошибках связываются с полем через `aria-describedby`
- Сообщения об ошибках — с `role="alert"` или `aria-live="polite"`, чтобы их объявлял скринридер
- У кнопки отправки явно указан `type="submit"`
- `novalidate` на `<form>` — когда валидация делается вручную в PHP/JS
- У всех обязательных полей есть атрибут `required`

### Типы полей

Каждому полю — правильный `type`:

- `type="email"` — email
- `type="password"` — пароли
- `type="tel"` — номера телефонов
- `type="number"` — числа
- `type="url"` — URL
- `type="search"` — поля поиска
- `type="date"` — даты
- `type="file"` — загрузка файлов
- `type="checkbox"` / `type="radio"` — выбор вариантов

## Изображения

```html
<!-- Растровое изображение -->
<img
	src="/assets/img/photo.jpg"
	alt="Brief description of what is shown"
	width="800"
	height="600"
	loading="lazy"
/>

<!-- Декоративное изображение — пустой alt, без ARIA -->
<img src="/assets/img/divider.svg" alt="" role="presentation" />

<!-- Адаптивное изображение с несколькими источниками -->
<picture>
	<source srcset="/assets/img/hero.webp" type="image/webp" />
	<img
		src="/assets/img/hero.jpg"
		alt="Hero image description"
		width="1440"
		height="600"
		loading="lazy"
	/>
</picture>

<!-- SVG-иконка inline -->
<svg aria-hidden="true" focusable="false" width="24" height="24">
	<use href="/assets/icons/sprite.svg#icon-name"></use>
</svg>
```

Правила:

- `alt` обязателен на каждом `<img>`; пустой `alt=""` — только для декоративных изображений
- Атрибуты `width` и `height` обязательны, чтобы не было сдвига макета (CLS)
- `loading="lazy"` — для изображений ниже первого экрана; `loading="eager"` — для критичных изображений первого экрана
- `<picture>` — для современных форматов (WebP) с запасным вариантом, только для статических ассетов
- Загруженные изображения выводятся только через `templates/components/responsive-image.tpl`:
  WebP-версии 1x/2x в `srcset` с дескрипторами ширины (`400w, 800w`) и `sizes`,
  без запасного варианта в `<picture>` (см. `docs/modules/images.md`)
- У декоративных inline SVG-иконок обязательны `aria-hidden="true"` и `focusable="false"`
- Если SVG несёт смысл — `<title>` внутри SVG или видимый/sr-only текст рядом

## Доступность (a11y)

### Основные принципы

- Все интерактивные элементы доступны с клавиатуры (Tab, Enter, Space, Escape, стрелки)
- У всех интерактивных элементов есть видимое состояние фокуса
- Цвет — не единственный способ передать информацию
- Контраст текста — не ниже WCAG 2.1 AA (4.5:1 для обычного текста, 3:1 для крупного)
- Обводку фокуса не убираем, не дав взамен своей видимой

### Управление фокусом

- Значения `tabindex` больше `0` не используем
- `tabindex="0"` — делает элемент фокусируемым в естественном порядке DOM (применять экономно)
- `tabindex="-1"` — убирает из порядка табуляции, но оставляет программный фокус (например, модальные окна)
- Модальное окно удерживает фокус, пока открыто, и при закрытии возвращает его на элемент, который его открыл

### Скрытый контент

```html
<!-- Скрыто от всех (скрыто через CSS) -->
<div hidden>...</div>

<!-- Визуально скрыто, но доступно скринридерам -->
<span class="sr-only">Additional context for screen readers</span>

<!-- Скрыто от скринридеров, видно на экране (декор) -->
<span aria-hidden="true">★★★★☆</span>
```

Для визуально скрытого контента в CSS должен быть определён утилитарный класс `sr-only`.

## ARIA

### Когда нужна ARIA

ARIA — только когда нативной семантики HTML не хватает.
Нативные элементы всегда предпочтительнее ARIA-ролей.

> Правило: лучше без ARIA, чем с неправильной ARIA.

### ARIA-роли

Роли — только когда роль элемента по умолчанию неверна или отсутствует:

```html
<!-- Правильно: нативная кнопка -->
<button type="button">Click me</button>

<!-- Только если элемент, не являющийся кнопкой, должен работать как кнопка -->
<div role="button" tabindex="0" aria-pressed="false">Custom button</div>
```

Частые роли:

- `role="alert"` — динамическое важное сообщение (объявляется автоматически)
- `role="status"` — несрочная живая область
- `role="dialog"` — модальное или диалоговое окно
- `role="navigation"` — ориентир навигации (лучше `<nav>`)
- `role="banner"` — шапка сайта (лучше `<header>` верхнего уровня)
- `role="main"` — основной контент (лучше `<main>`)
- `role="contentinfo"` — подвал (лучше `<footer>` верхнего уровня)
- `role="search"` — контейнер формы поиска
- `role="presentation"` / `role="none"` — убирает элемент из дерева доступности

### ARIA-состояния и свойства

```html
<!-- Интерактивные состояния -->
aria-expanded="true|false"
<!-- раскрываемый блок: открыт/закрыт -->
aria-checked="true|false"
<!-- состояние чекбокса/переключателя -->
aria-selected="true|false"
<!-- выбранный элемент в listbox/вкладках -->
aria-pressed="true|false"
<!-- кнопка-переключатель -->
aria-disabled="true"
<!-- неактивное состояние (когда атрибут disabled не используется) -->
aria-hidden="true"
<!-- скрыть из дерева доступности -->
aria-current="page|step|..."
<!-- текущий элемент в наборе (хлебные крошки, пагинация) -->

<!-- Связи -->
aria-label="..."
<!-- доступное имя, когда видимой подписи нет -->
aria-labelledby="id"
<!-- указывает на видимый элемент, который подписывает этот -->
aria-describedby="id"
<!-- указывает на элемент, который описывает этот -->
aria-controls="id"
<!-- указывает на элемент, которым управляет этот -->
aria-owns="id"
<!-- объявляет владение элементом вне дерева DOM -->

<!-- Живые области -->
aria-live="polite|assertive"
<!-- объявление динамического контента -->
aria-atomic="true"
<!-- при изменении объявлять всю область целиком -->
```

Правила:

- `aria-label` не дублирует видимый текст — в этом случае `aria-labelledby`
- Не добавляем `aria-label` на `<div>` или `<span>` без роли
- Не ставим `aria-hidden="true"` на фокусируемые элементы
- Не ставим `role="button"` на `<a>`, если ссылка ведёт на другую страницу — нужен `<button>`

### Навигация и ориентиры

На каждой странице чётко заданы ориентиры для навигации скринридером:

- Один `<header>` (или `role="banner"`) верхнего уровня
- Один `<main>` (или `role="main"`)
- Один `<footer>` (или `role="contentinfo"`) верхнего уровня
- Если блоков `<nav>` больше одного, у каждого уникальная подпись:
    ```html
    <nav aria-label="Main navigation">...</nav>
    <nav aria-label="Breadcrumbs">...</nav>
    ```

## Интерактивные компоненты

### Кнопки и ссылки

- `<button>` — запускает действие (отправить форму, открыть модальное окно, переключить состояние)
- `<a href="...">` — переход по URL или якорю
- `<a>` без `href` для действий не используем — нужен `<button>`
- `<div>` и `<span>` не делаем интерактивными, если только это не вынужденно технически и не добавлена ARIA

### Модальные окна / диалоги

```html
<dialog
	id="modal"
	role="dialog"
	aria-modal="true"
	aria-labelledby="modal-title"
>
	<h2 id="modal-title">Dialog Title</h2>
	<p>Dialog content...</p>
	<button type="button" aria-label="Close dialog">✕</button>
</dialog>
```

Правила:

- По возможности — нативный `<dialog>`
- `aria-modal="true"` сообщает скринридеру, что остальная страница неактивна
- `aria-labelledby` указывает на заголовок диалога
- У кнопки закрытия понятный `aria-label`
- Пока диалог открыт, фокус удерживается внутри

### Вкладки

```html
<div role="tablist" aria-label="Content tabs">
	<button role="tab" aria-selected="true" aria-controls="panel-1" id="tab-1">
		Tab One
	</button>
	<button
		role="tab"
		aria-selected="false"
		aria-controls="panel-2"
		id="tab-2"
		tabindex="-1"
	>
		Tab Two
	</button>
</div>
<div role="tabpanel" id="panel-1" aria-labelledby="tab-1">...</div>
<div role="tabpanel" id="panel-2" aria-labelledby="tab-2" hidden>...</div>
```

### Раскрывающийся блок (аккордеон)

```html
<button type="button" aria-expanded="false" aria-controls="section-body">
	Section Title
</button>
<div id="section-body" hidden>Content...</div>
```

## Ссылки

Правила:

- Текст ссылки описывает, куда она ведёт — никаких одиноких «нажмите здесь» или «подробнее»
- Если визуально нужен общий текст, добавляем скрытый контекст:
    ```html
    <a href="/posts/my-post">
    	Read more <span class="sr-only">about My Post Title</span>
    </a>
    ```
- Внешние ссылки сообщают, что откроются вовне:
    ```html
    <a href="https://example.com" target="_blank" rel="noopener noreferrer">
    	External site <span class="sr-only">(opens in new tab)</span>
    </a>
    ```
- `target="_blank"` — всегда в паре с `rel="noopener noreferrer"`

## Таблицы

`<table>` — только для табличных данных, никогда для вёрстки.

```html
<table>
	<caption>
		Monthly sales report
	</caption>
	<thead>
		<tr>
			<th scope="col">Month</th>
			<th scope="col">Sales</th>
		</tr>
	</thead>
	<tbody>
		<tr>
			<th scope="row">January</th>
			<td>1200</td>
		</tr>
	</tbody>
</table>
```

Правила:

- `<caption>` обязателен — описывает назначение таблицы
- `<thead>` и `<tbody>` обязательны
- Ячейки заголовков — `<th>` со `scope="col"` или `scope="row"`
- В сложных таблицах ячейки связываются атрибутами `id` + `headers`

## Именование и атрибуты

### Классы

- Именование по BEM, согласованно с правилами CSS
- Классы описывают смысл, а не внешний вид
- Никаких случайных сокращений

### ID

- ID уникальны в пределах страницы
- ID нужны для: подписей (`for`/`id`), ссылок ARIA, якорных ссылок, JS-хуков
- ID не используем для стилей

### Data-атрибуты

- `data-*` — для JS-хуков и хранения состояния
- `data-*` не используем как триггеры стилей — для этого классы

### Свои JS-хуки

- Цели для JavaScript — через `data-*` или отдельный префикс класса (например, `js-*`)
- JS-поведение никогда не вешаем на классы оформления
    ```html
    <!-- Правильно -->
    <button class="btn btn--primary js-open-modal" data-modal="login">
    	Login
    </button>
    ```

## Производительность

- `loading="lazy"` — для изображений и iframe ниже первого экрана
- `<link rel="preload">` — для критичных ресурсов первого экрана, если нужно
- Без огромных DOM-деревьев — вложенность в разумных пределах
- Не выводим невидимую или дублирующую разметку ради вёрстки
- `<template>` — для повторяющихся структур, которые рендерит JS, если это применимо

## Правила для ИИ

ИИ обязан:

- следовать семантической структуре HTML5
- использовать теги по их смыслу
- добавлять `alt` ко всем изображениям (пустой `alt=""` — только для декоративных)
- использовать ARIA-атрибуты, когда нативной семантики недостаточно
- делать формы доступными: парные подписи, сообщения об ошибках через `aria-describedby`
- использовать `aria-label` / `aria-labelledby`, когда видимой подписи нет
- сохранять доступность всех интерактивных элементов с клавиатуры
- использовать `<button>` для действий и `<a href>` для навигации
- задавать `width` и `height` у элементов `<img>`
- добавлять атрибут `lang` к `<html>`

ИИ запрещено:

- использовать `<div>` или `<span>` как интерактивные элементы без ARIA и поддержки клавиатуры
- ставить `aria-hidden="true"` на фокусируемые элементы
- пропускать уровни заголовков
- использовать placeholder вместо подписи
- использовать `<table>` для вёрстки
- добавлять `role="button"` ссылкам, которые ведут на другую страницу
- использовать значения `tabindex` больше 0
- использовать `target="_blank"` без `rel="noopener noreferrer"`
- добавлять лишнюю ARIA, которая дублирует нативную семантику
- писать неверный или бессмысленный текст `alt`
- использовать устаревшие HTML-теги

## Definition of Done

HTML готов, когда:

- структура документа валидна и начинается с `<!DOCTYPE html>`
- есть `lang`, `charset`, `viewport` и `description`
- иерархия заголовков логична и последовательна
- все семантические теги использованы по назначению
- у всех изображений есть `alt` и атрибуты размеров
- у всех полей формы есть парные `<label>`
- ARIA там, где нужна, использована правильно
- все интерактивные элементы доступны с клавиатуры
- нет таблиц для вёрстки
- у ссылок понятный текст
- внешние ссылки используют `rel="noopener noreferrer"`
- разметка проходит валидацию W3C HTML
- разметка проходит базовую проверку доступности (axe, WAVE или аналог)
